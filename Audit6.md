# Laporan Audit Global Tahap 6 (Source Code Aktual)

**Status:** Selesai
**Metode:** Inspeksi statis & analisis fungsional berdasarkan alur logika kode aktual
**Cakupan:** `app/src/main/java`, `app/src/test`, `AndroidManifest.xml`, `res/`, dan konfigurasi Gradle.

Berikut adalah temuan fungsional yang terbukti berdampak pada arsitektur, stabilitas, dan keandalan sistem Silauncer:

### Daftar Temuan

| ID | Severity | File | Class/Method | Bukti | Akar Masalah | Dampak | Rekomendasi |
|---|---|---|---|---|---|---|---|
| **[CLOSED] BUG-LONGPRESS-COORDS** | High | `app/src/main/java/com/silauncer/cepat/touch/CheckLongPressHelper.kt` | `pointInView` | `return localX >= v.left - slop && localY >= v.top - slop ...` | Menggunakan properti `v.left` / `v.top` (koordinat ruang parent) untuk memvalidasi parameter `localX` / `localY` (`ev.x` / `ev.y`) yang merupakan koordinat relatif lokal dari View itu sendiri. | Jitter kapasitif memicu `ACTION_MOVE`, yang lalu dievaluasi salah oleh `pointInView`. Ini seketika membunuh `cancelLongPress()`, membuat interaksi tahan-lama (long-press) pada grid menjadi mustahil atau sangat sulit terpicu jika jari bergerak meski hanya 1 piksel. | Ubah kalkulasi batas menjadi berbasis ruang lokal: `localX >= -slop && localY >= -slop && localX < (v.width + slop) && localY < (v.height + slop)`. |
| **[CLOSED] BUG-DIFF-MUTABLE** | Medium | `app/src/main/java/com/silauncer/cepat/home/LauncherItemDiffCallback.kt` | `areContentsTheSame` | `old.appInfo == new.appInfo` pada mutable class | `AppInfo` adalah data class yang bersifat mutable (`var hasNotification = false`). Karena objek di-cache secara statis (lewat `WorkspaceCache`), mutasi terhadap notifikasi terjadi secara *in-place*. Saat DiffUtil dipanggil via `submitLauncherItems`, `oldList` dan `newList` akan menunjuk pada referensi memory yang sama. Evaluasi *equality* selalu me-return `true`. | Panggilan lazim pembaruan *notification dot* yang murni bersandar pada DiffUtil akan dilewati (diabaikan) oleh RecyclerView, menimbulkan inkonsistensi rendering notifikasi bila *notifyItemChanged* tidak dipanggil secara eksplisit. | Biasakan immutability. Ubah variabel pada `AppInfo` menjadi `val` dan ciptakan kloning objek dengan fungsi `copy()` saat state berubah. |
| **[CLOSED] BUG-LIFECYCLE-STATE** | Medium | `app/src/main/java/com/silauncer/cepat/launcher/LauncherActivity.kt` | *Lifecycle* | Tidak adanya preservasi state modal maupun konfigurasi rotasi. | Launcher di Android secara kodrat sering terkena event rotasi atau transisi lipatan layar. Activity tidak menggunakan `android:configChanges` ataupun mengekstrak preservasi state UI (seperti open/close folder) ke dalam `onSaveInstanceState`. | Apabila pengguna sedang membuka folder modal dan layar merotasi, `LauncherActivity` akan dihancurkan (destroyed) dan direkonstruksi, menyebabkan tampilan Folder tertutup tiba-tiba, serta scroll kembali ke atas (state hilang). | Tambahkan `android:configChanges="keyboard|keyboardHidden|orientation|screenSize|screenLayout|smallestScreenSize|uiMode"` pada manifest `LauncherActivity`, atau tangkap dan pulihkan state folder/scroll via `Bundle`. |
| **[CLOSED] BUG-DISK-RACE-CONDITION** | Medium | `app/src/main/java/com/silauncer/cepat/cache/DiskIconCache.kt` | `put` / `get` | `if (file.exists() && file.length() > 0L)` tanpa implementasi *lock* | Operasi I/O file pada background IO thread (Coroutine) tidak disinkronisasi. Pembacaan gambar dengan `BitmapFactory.decodeFile` berisiko besar terjadi bersamaan saat thread lain baru saja membuka `FileOutputStream` dan baru memulai proses kompresi bitmap. | `decodeFile` mungkin mengembalikan error (null) karena membaca data PNG/WEBP yang belum lengkap (parsial header), menyebabkan cache disk seolah gagal, memicu komputasi IPC ulang ke sistem OS, membuang sumber daya secara berlebihan. | Gunakan coroutine `Mutex` berjenjang untuk mencegah eksekusi konkurensi pembacaan pada *key* yang sama saat penulisan (buffer flush) sedang beroperasi. |

> Catatan: Pemeriksaan read-only membuktikan bahwa isu di atas benar-benar ada pada runtime operasional aktual tanpa mengubah sebaris pun kode program. Penggalian berpusat pada stabilitas dan skalabilitas Launcher.
